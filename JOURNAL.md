## 2026-10-06 — Анкета бесплатного ИИ-аудита готова

Бесплатный ИИ-аудит теперь заказывается через пошаговую анкету из семи вопросов: два
обязательных (бизнес и главная боль), остальные можно пропустить. Анкета открывается на
странице `/audit` и прямо в чате, когда модель определила запрос как аудит; при ручном
разборе её тоже предлагают вместо прежних двух вариантов. Вход в неё есть из меню, из списка
примеров в чате и со страницы услуги «ИИ-аудит процесса».

Что делает форма удобной: счётчик символов в текстовых полях, подсказка об обязательности,
автофокус при переходе между шагами, `Ctrl/⌘+Enter` для «Далее», подрезка лишних пробелов,
«Начать заново» без подтверждения после отправки. Ответы сохраняются вместе с текстом
вопросов, поэтому заявка читается без справочника; текст вопросов и допустимые варианты
подставляет сервер из своего списка, а не из запроса браузера.

Размер анкеты ограничен на трёх уровнях (форма, сервер сайта, API), в уведомлении Telegram
ответы выводятся парами «вопрос и ответ», реплики из чата прикладываются последней парой.
Страница `/privacy` дополнена описанием ответов анкеты; модель их не получает.

Проверено живьём до Telegram: оба пути (страница и чат) доходят до базы и уведомления.

## 2026-10-05 — КП в заявке и первая часть анкеты ИИ-аудита

Заявка теперь несёт КП, которое видел клиент: в таблице `lead` новая необязательная
колонка `proposal` (JSON), миграция и ER-схема обновлены. API принимает КП вместе с
контактом и режет его по размеру (20 КБ, в байтах UTF-8, а не символах: кириллица
занимает по 2 байта). Сайт отправляет КП только для обычного предложения, не для
аудита и ручного разбора, и проверяет тип и размер до обращения к API.

Уведомление в Telegram перестроено: шапка (имя, контакт, услуга, номер заявки)
идёт целиком, а режется только тело, чтобы длинное КП не унесло контакт. КП
показано кратко: название, задача, состав работ, допущения, что не входит, срок и
цена, если они есть, с подписью «со слов сайта» (КП приходит из браузера, сервер
его не проверял). Страница `/privacy` дополнена описанием КП в составе заявки.

Анкета бесплатного ИИ-аудита: в Telegram ответы выводятся парами «вопрос и ответ»,
лимит размера поставлен и на них. Подготовлены список из семи вопросов, сборка
ответов на сервере сайта (текст вопросов и варианты берутся из нашего списка, а не
из запроса) и логика пошагового визарда. Сама форма и страница `/audit` — следующий
шаг.

## 2026-10-02 — Приём заявок в API и уведомление в Telegram

В таблицу `lead` добавлена необязательная колонка `audit_answers` (JSON) для
ответов анкеты бесплатного аудита; миграция и ER-схема обновлены, поведение
проверено тестом на живой базе.

Добавлен адрес `POST /api/v1/intake/contact`: принимает имя, контакт, тип услуги
и, по желанию, ответы анкеты и идентификатор разговора. Данные проверяются
через DTO-класс (обрезка пробелов, лимит 200 символов, допустимые значения
типа услуги, лишние поля отклоняются). Лид создаётся и разговор привязывается
в одной транзакции: если разговор не найден (404) или уже занят (409), лид не
остаётся в базе. Привязка выполняется одним запросом с условием «разговор ещё
без лида», поэтому два одновременных запроса на один разговор не привяжут его
дважды. Покрыто 12 сквозными тестами.

После успешного создания лида API отправляет уведомление в Telegram
(`TelegramNotifier`). Токен бота и идентификатор чата задаются переменными
окружения парой; без них уведомления выключены (локальная разработка и
тесты). Уведомление уходит после завершения транзакции, поэтому откатанный
лид не попадает в чат. Сбой отправки не мешает приёму заявки и только
пишется в лог, токен в тексты ошибок и логов не попадает. Текст посетителя
отправляется без разметки. В сквозных тестах уведомитель всегда подменён, чтобы
прогон тестов не слал настоящие сообщения.

## 2026-10-01 — Тексты услуг, страница «Настройка VPS» и переключатель темы

Тексты всех одиннадцати услуг вычитаны: убран технический жаргон из описания
автодеплоя, цены хранятся в одном месте (поле `price`) и не дублируются в
пояснениях, расширено описание сопровождения (сроки ответа, как учитываются
расходы на ИИ). Для услуг, которым нужен сервер (боты, сервисы), добавлена
фраза про сервер и ссылка на услугу по его настройке.

Услуга про сервер переработана в «Настройку VPS». В описание услуги добавлено
необязательное поле `explainer` с блоком «Что такое VPS и зачем он нужен», он
выводится первым на странице услуги. Остальные услуги поле не используют и
выглядят как раньше.

Переключатель темы теперь читает тему через `useSyncExternalStore` и
подписывается на изменение класса `dark` у корневого элемента, вместо
копирования значения в состояние через эффект. Это закрыло ошибку линтера
(`react-hooks/set-state-in-effect`): сборка её не показывала, потому что
`next build` линтер не запускает, а `npm run lint` ругался.

## 2026-09-30 — Эпик 10: сущность `lead` и первая миграция

Выбран ORM — Prisma 7 (версия закреплена, Prisma 8 пока в статусе релиз-
кандидата). Описана сущность `lead` (контакт, имя, вид услуги, пожелания по
бюджету и срокам, статус, время создания и обновления; идентификатор UUID) и
заведена первая миграция, применённая к базе в контейнере. Клиент Prisma
генерируется командой `npm run prisma:generate` и в git не хранится.

Добавлен сервис доступа к базе (`PrismaService`): один клиент на приложение,
адрес берётся из проверенного конфига, при старте выполняется пробный запрос
(если база недоступна, приложение не запускается), при остановке соединения
закрываются корректно. Покрыто тестами на живой базе.

Настройка приложения (префикс `api/v1`, проверка входящих данных, корректная
остановка) вынесена в одну функцию, которую используют и запуск сервера, и
автоматические тесты. Глобально включена строгая проверка входящих данных:
лишние поля отклоняются с ошибкой 400. Закрыт пробел в тестах: раньше они не
видели общий префикс адресов.

Добавлена таблица разговоров (`conversation`) и вторая миграция: связь с
лидом необязательна (разговор начинается раньше, чем появляется лид), лида с
разговорами удалить нельзя. Правила проверены тестами на живой базе, схема
базы описана в `docs/database.md`.

Добавлен первый рабочий адрес чата, `POST /api/v1/intake/start`: заводит
разговор и возвращает идентификаторы и первый вопрос ассистента (пока
постоянный текст, сценарий будет отдельным шагом). Модуль подключён к базе, и
запуск без базы теперь завершается понятной ошибкой. Покрыто юнит-тестами и
сквозным тестом на живой базе.
