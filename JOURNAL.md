## 2026-08-31 — Эпик 1 Этапа 1: scaffold `apps/web`

`apps/web` — Next.js 16.3.3, TypeScript, Tailwind, App Router, `src/`
директория, alias `@/*`. Монорепо-раскладка: `apps/web` — отдельное
Next.js-приложение внутри репозитория.

Команда:

```bash
mkdir -p apps && cd apps
npx create-next-app@latest web --typescript --eslint --tailwind --app \
  --src-dir --import-alias "@/*" --use-npm
```

Проверено вживую: `npm run dev` → `localhost:3000` → `200`, процесс
остановлен после проверки. Закоммичено (`ad52d2d`, не запушено).

**Грабли:** `npx create-next-app@latest apps/web ...` (путь в один
вызов) падает с ложной ошибкой `The application path is not writable`,
если `apps/` ещё не существует — баг самого `create-next-app` (не
создаёт промежуточные директории перед проверкой прав), не реальная
проблема с правами (проверено `touch`/`node fs.accessSync` — всё
писалось нормально). Фикс — создать `apps/` заранее (`mkdir -p`),
скаффолдить `web` уже внутри неё как одноуровневый путь. Зафиксировано
как переиспользуемый скилл:
`~/.claude/skills/create-next-app-nested-path-fix/SKILL.md`.

**Заметка на будущее:** Next.js 16 сам сгенерировал `apps/web/AGENTS.md`
(и `CLAUDE.md` со ссылкой на него) с предупреждением, что у этой версии
есть breaking changes относительно возможных обучающих данных модели —
перед написанием кода сверяться с `node_modules/next/dist/docs/`. Файл
родной, не трогать.
